# Non-Functional Requirements

## Introduction

Non-functional requirements describe some of the characteristics that the system should have.

For Bella Dona ERP, we considered usability, security, availability, performance, responsiveness, maintainability, and scalability.


## 1. Usability

The system should have a simple and easy-to-understand interface.

The main options should be easy to find, so users can perform their activities without unnecessary steps.

### Justification

Usability is important because the main purpose of the ERP is to make business management easier.



## 2. Security

The system should have different access levels according to the user's role.

The proposed roles are:

- Administrator.
- Salesperson.
- Inventory Manager.
- Customer.

### Justification

The ERP will contain information about sales, customers, suppliers, products, and inventory.

For this reason, users should only have access to the information they need.



## 3. Availability

The system will be developed as a web application.

The objective is to allow users to access the system through the Internet.

### Justification

A web system makes it possible to access business information without depending on only one computer.



## 4. Responsive Design

The interface should work correctly on different screen sizes, including:

- Desktop computers.
- Laptops.
- Tablets.
- Mobile devices.

### Justification

Users may need to consult information using different devices.



## 5. Performance

The system should respond in a reasonable amount of time when users:

- Search for products.
- Check inventory.
- Register sales.
- Search for customers.
- Generate reports.

### Justification

Good performance will make the daily use of the system easier.



## 6. Maintainability

The system should be organized in a way that allows changes and improvements to be made more easily.

### Justification

The business may need new functions in the future.



## 7. Scalability

The system should allow the number of products, customers, suppliers, sales, and users to increase over time.

### Justification

The ERP should be able to grow together with Bella Dona.



# Visual Identity

Bella Dona ERP should have a name, a commercial image or logo, and a consistent color palette.

The visual style will be based on the gothic identity of Bella Dona.



## Color Palette

| Element | Color |
|---|---|
| Main Background | Obsidian Black |
| Main Color | Gothic Purple |
| Highlight Color | Red |
| Text | Chalk White |



## Interface Design

The interface should include:

- Clear navigation.
- Readable text.
- Organized forms.
- Consistent buttons.
- Clear sections.
- Responsive design.
- Consistent colors.

The objective is to create an interface that matches the style of Bella Dona and is also easy to use.


## Summary

The non-functional requirements are important because the system should not only perform the required functions, but should also be easy to use, secure, accessible, and organized.
